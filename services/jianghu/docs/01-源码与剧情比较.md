# 源码与剧情比较

版本：v0.1；研究日期：2026-10-19；结论性质：静态源码比较，非完整试玩评测。

## 1. 研究对象与证据边界

| 对象 | 上游 | 本次固定提交 |
| --- | --- | --- |
| 炎黄群侠传 | https://github.com/oiuv/mud | `2d0d54bdf0a68218dcbe9cc60ddf60d13d249704` |
| 侠客行 100 | https://github.com/fluffos/xkx100 | `c1b87db0014c85514e053b2a149a2efccb9914e3` |

沿用前一轮确定的 fluffos/xkx100，不与 MudRen/xkx100 混用。两份源码已下载到 `research/sources/`，未运行安装脚本、驱动或 AI 服务。没有访问在线游戏的玩家数据。

本轮包括全库静态计数，以及新手任务、阵营选择、跨城线索、世界故事、重复任务、网页协议的定向抽样。没有逐条阅读全部剧情，也没有证明任何任务可通关。下述优劣是选型建议，不是最终质量评分。

## 2. 内容体量：侠客行更大，但不等于故事更深

复现方式：项目根目录运行 `python3 research/inventory.py`。完整结果见 `research/source-inventory.json`。

| 静态指标 | 炎黄 | 侠客行 100 |
| --- | ---: | ---: |
| `.c` / `.lpc` 文件 | 9,980 | 12,192 |
| `d/` 下一级目录 | 72 | 87 |
| 直接匹配 `inherit ROOM;` 的文件 | 4,357 | 5,682 |
| 匹配 NPC 继承模式的文件 | 1,574 | 2,385 |
| 设置 `inquiry` 对话表的文件 | 376 | 561 |
| 其中位于 `d/` 的对话表文件 | 165 | 340 |
| `kungfu/class/` 下一级目录 | 42 | 31 |

口径限制：这是文件特征计数，包含可能的副本、旧文件、测试和不可达对象；不包含未下载子模块；不会识别所有间接继承或数据驱动对象。目录不是独立区域或有效门派数；对话文件不是故事条数；不据此计算剧情时长、去重地图数或完整 NPC 数。炎黄部分装备已数据化，源码文件数尤其不宜直接比较资产量。

可以支持的结论：侠客行 100 在本快照中拥有更大的传统场景和静态对话候选池。不能支持的结论：侠客行剧情必然更好，或炎黄门派必然更多。

## 3. 炎黄：较适合组织首版体验

### 连续新手任务

`adm/daemons/quest/_0_tutorial1.c` 至 `_0_tutorial7.c` 包含打铁、存钱、食物、郭府打工、拜师、每日福利、师门任务。后续任务可检查前一任务是否完成；首项打铁检查工作记录达到 20 次。

价值：已有从生存到入门的成长骨架，适合接任务日志和按钮。问题：其中包含重复劳动及每日福利，不应照单全收作为首版故事；试验服可压缩重复次数，但须记录为我们改动的数值。

### 有明确后果的阵营选择

`adm/daemons/quest/_1_mao18.c` 与 `_1_shisong.c` 是“茅十八的友谊 / 史松的友谊”。接取条件排除另一任务的进行或完成状态；双方目标、交付物不同，茅十八路线还开放刀法学习。

价值：已有选择、对立、奖励和成长的连接，最适合作为首段故事候选。尚待运行核对：放弃后能否换边、死亡后目标如何刷新、奖励是否只发一次、各条路径能否走通。不能把它描述为已覆盖完整《鹿鼎记》剧情。

### 世界故事不全是可操作任务

`adm/daemons/storyd.c` 调度 `story/` 中的脚本。以 `story/sanfenjian.c` 为例：筛选满足红花会、经验和剑术条件的在线角色，分步播报霍青桐相关故事并授予武学。

价值：有江湖氛围和武学奇遇素材。问题：此样本主要是播报与授奖，并非玩家主动参与的完整冒险。首版不等待随机故事触发；可在后期选择性改为场景事件。

### 网页接入更有基础

`www/README.md` 和 `www/client.js` 提供中文输入、WS/WSS、终端及移动端支持；`feature/user_gmcp.c` 有角色状态和房间信息响应。但现有房间响应并不等于完整的可点击地图、NPC、背包、任务协议；仍须补充结构化接口。

## 4. 侠客行 100：适合发掘探索型故事

### 跨 NPC、跨城的叫化鸡线索

可以在源码中连接到以下节点：

1. `kungfu/class/taohua/rong.lpc`：向黄蓉问叫化鸡，设置首个临时标记。
2. `d/city/task3/shiye.lpc`：谭友纪根据该标记提供北京线索，推进标记。
3. `d/beijing/npc/cheng.lpc`：程老板根据引荐标记回应；正确状态下交付指定金额可得到叫化鸡。
4. `kungfu/class/gaibang/hong.lpc`：洪七公接受该食物并设置有关收徒的临时条件；收徒还受其他条件限制。

价值：问消息、跨城旅行、交付物品、人物关系和学艺自然连接，比菜单派发任务更有发现感。风险：关键节点使用临时状态，重连后延续性、NPC 刷新及金钱门槛要实际核查；目前不能承诺“送鸡即学降龙十八掌”。

### 官府与护送玩法

`d/city/task1/yayi.lpc` 有揭文书悬赏的提示，`task2/renzhi.lpc` 有护送人质、遇险与逃离逻辑，`task3/shiye.lpc` 有入官府条件。它们可提供不同于单纯打怪的任务素材；尚未验证三个目录之间构成一条连续主线。

### 重复委托不能充当长篇剧情

`quest/weixiaobao.lpc` 包含鲜明的人物对话、连续收集委托、取消代价和奖励。`adm/daemons/questd.lpc` 读取动态任务及地点表。它们支持长期游玩，但“能刷很多任务”不代表“有很多不同故事”。首版只保留少量有叙事意义的委托。

### 网页入口可用性仍需实测

README 记载网页端口及 UTF-8 升级，同时承认地图排版、表情和翻译缺漏。`www/` 有终端客户端；不能因为有网页入口就认定已具备 2D 图形界面。

## 5. 选型与取长补短

| 维度 | 当前判断 | 做法 |
| --- | --- | --- |
| 传统世界候选体量 | 侠客行更大 | 作为区域、NPC、支线素材库，逐条挑选 |
| 新手路径与任务表达 | 炎黄样本更便于组织 | 保留其任务条件与生命周期，简化重复劳动 |
| 探索式线索 | 侠客行叫化鸡样本突出 | 保留人物关系和发现过程，补持久进度与适度提示 |
| 明确阵营选择 | 炎黄已有可参考实现 | 首段体验采用茅十八 / 史松两条独立可测分支 |
| 动态江湖氛围 | 炎黄有故事调度样本 | 后置，避免依赖长等待和纯播报 |
| 图形网页接入 | 暂优先炎黄 | 在现有协议上补足状态和动作接口 |
| 完整长篇主线 | 两者均未证实 | 从已验证故事串联小章节，不承诺现成小说全流程 |

暂定结论：炎黄为主、侠客行为辅，先验证再锁定。整合单位是一条故事及其依赖，不是整个目录；只保留一套战斗、成长、任务结算和存档规则。

## 6. 后续必须解答

- 两套分别能否在隔离环境启动并完成选定故事？
- 所选 NPC 是否真实生成、地图是否可达、隐藏门槛是否合理？
- 叫化鸡链在炎黄是否已有同源实现？先对照，避免重复移植。
- 被抽中的故事是纯播报、重复委托，还是有可执行的状态推进？
- Mac 环境采用容器还是原生驱动更容易复现？运行验证后决定。
